# Milestone v5.0 — Experiment Rig (Stochastic Tick Process on the CFMM Kernel)

Status: DRAFT — pending two-step review + user approval. Nothing here executes without per-item
user sign-off. Heavy-intervention mode: no autonomous coding agents.

## Overview

v5.0 makes the merged `PriceSetterHook` (PR #11) *useful*: it turns the "single entry point for
setting the tick" into a **running experiment rig** that imposes a stochastic process on a pool's
tick, so many replication/vega experiments can be driven from off-chain. It is the direct
successor to v4.0's vol-order registry and the price-setter hook — those built the *mechanism*
(write the tick; register vol orders); v5.0 builds the *driver and the surfaces it feeds*.

Phases continue at **20** (v1.0 = 1–7 paused, v2.0 = 8–11 partial/paused, v3.0 = 12–15 shipped,
v4.0 = 16–19 shipped). v5.0 phases are a new track; existing phases are never renumbered.

Scope is bounded by the backlog coverage ledger (`.planning/backlog-coverage-ledger.md`): **only
items whose deliverable is `src/` or `test/` code in this worktree.** lib/ submodule studies, the
rpc_api Haskell peer, the paused v2.0 vol-diff, and pure-research questions are OUT (accounted for
in the ledger, folded in as design inputs where relevant).

**Executable spec (user, 2026-07-27):** the `todo.md` items and the inline **code-comment sketches**
in both files are the authoritative build targets. notes/STOCHASTIC_MODEL.md *prose/math* (the λ/Poisson/LogNormal
derivation) is **secondary context, not a build target.** The imposed process is therefore in
**TICK space** on a **no-liquidity** pool — the `ExchangeRateDifussion` type sketched in `todo.md`§14,
not the NOTES amount-process. This resolves the two-step review's B1 (amount↔tick), B1-LogNormal
(no on-chain Gaussian primitive), and the moment-check falsifiability major — all of which were
tied to the now-secondary NOTES math.

**Hard constraints (carried from prior milestones — enforced every phase):**
- **"It compiles" is NEVER acceptance.** Plank does not type-check code unreachable from `run{}`;
  a `.plk` claim is proven only by CALLING it through FFI-deployed bytecode. Solidity claims are
  proven by a passing/failing forge test, never by a green build.
- **A tick write is `setStorageAt` on the node, not an in-script `vm.rpc` mutation** (v5.0 inherits
  the PriceSetterHook finding: in-script `vm.rpc("anvil_setStorageAt")` applies then reverts the
  script frame — mutating RPC goes through `cast`/the make target).
- **The v5.0 pool regime is NO-LIQUIDITY** — a slot0 write does not maintain liquidity/tickBitmap/
  feeGrowth (the PriceSetterHook coherence boundary), and v5.0 imposes a pure tick process, so there
  is no LP position to keep coherent. (Fee/vega experiments needing liquidity are a later fixture,
  flagged in Phase 23.)
- **The tick-driver PROOF is a forge test** using the hook's `TickCheat`/`vm.store`→`vm.load` path
  (in-process, assertable), NOT the external `cast rpc anvil_setStorageAt` live-node path — a forge
  test cannot assert on an out-of-process write. The live-node make-target is a convenience, not the
  proof surface.
- Corpora CONSTRUCTED, not `vm.assume`-filtered; a non-fuzz anchor beside every fuzz.
- Every forge invocation uses the gate's flags (`--via-ir --optimize`, `--offline` where cached).

## Phase Details

### Phase 20 — `ExchangeRateDifussion` Tick-Space Driver — DELEGATED (off-chain Haskell)
**Status (2026-07-28):** OUT of v5.0 build scope. The `ExchangeRateDifussion` calls are made
off-chain (rpc_api Haskell track), imposing the tick via `setStorageAt` against the shipped
PriceSetterHook. The on-chain prerequisite is done; the driver itself is the peer's. The design
below is retained as the CONTRACT the off-chain driver honors, not as our deliverable.

**Goal**: The `ExchangeRateDifussion` type from `todo.md`§14 exists as buildable code: a tick-space
process, configured by a `StochasticConfig`, that produces `nObs` tick observations and drives them
through `PriceSetterHook` on a no-liquidity pool — with the realized on-chain trajectory verified in
a forge test exactly as the hook's single-write test already proves one write.
**Requirements**: EXPR-01, EXPR-02, EXPR-03
**Success Criteria** (what must be TRUE):
  1. A **no-liquidity** experiment fixture exists — PoolManager + a flag-mined `PriceSetterHook` +
     a bound pool with NO LP position (regime named, justified against the coherence boundary; the
     NOTES concentrated −120/+120 position is explicitly NOT used, per the reframe) (EXPR-01).
  2. `ExchangeRateDifussion { poolId, config: StochasticConfig }` is implemented with a **pure**
     `observe(nObs) -> int24[]` producing the tick trajectory from the config, reproducibly (same
     config/seed → identical trajectory), every tick in `[MIN_TICK, MAX_TICK-1]`. The first concrete
     `StochasticConfig` is a deterministic tick process (the tick-space analog of the NOTES proxy —
     the amount math is secondary reference); a pseudo-random tick-walk config, if added, carries an
     explicit seed. This is the `todo.md` code sketch, built VERBATIM in shape (EXPR-02).
  3. An **effectful** `drive(nObs)` writes each observed tick through the hook via `TickCheat`
     (`vm.store` of `hook.packSlot0For(tick)`), and a forge test asserts the realized on-chain
     trajectory (read via `vm.load`/`hook.readTick`) EQUALS `observe(nObs)` element-for-element,
     with `sqrtPriceX96 == getSqrtPriceAtTick(tick)` and fee bits preserved at every step. A
     falsifiability anchor: a frozen-tick config and a wrong-drift mutant are each CAUGHT (EXPR-03).
**Not in scope (secondary per reframe):** the LogNormal/Poisson amount process, on-chain Gaussian
sampling, and the `E[Δy]=Δȳ` moment check — those live in NOTES prose and are deferred. The
live-node `cast rpc` make-target driver is a convenience wrapper, not a Phase-20 proof deliverable.
**Plans**: TBD (per-item, user-approved)

### Phase 22 — LDF Type System
**Goal**: The liquidity-density-function type surface exists as a typed, tested Plank module —
`PriceCoordinate` (TickBitmap<TickSpacing>, basis 1.0001, sub-elasticity, opt. Q64.96), `PricePair`,
`PriceOrderedPair`, `PriceBucket`, and the `TickBucket → PriceBucket` map.
**Requirements**: EXPR-07, EXPR-08
**Success Criteria**:
  1. The `PriceCoordinate`/`PricePair`/`PriceOrderedPair`/`PriceBucket` constructors are CALLED-green

     and `TickBucket → PriceBucket` are each CALLED-green with a falsifiability anchor (EXPR-08).

`src/lib/LiquidityAmounts.plk` already `import types::PricePair::*` and `types::PriceBucket::*` (no
