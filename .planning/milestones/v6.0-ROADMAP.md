# Roadmap: mev_tax_model_one — on-chain VolumePath execution (v6.0)

**Created:** 2026-08-16
**Status:** Self-contained milestone doc (Option A). Phases numbered from 20 (past the live
mega-roadmap's Phase 19). Review gate waived by user for this doc.

## Overview

Prove the mev_tax_model_one closed loop on-chain: the GAMS-computed `dQx` VolumePath, executed on a
real Algebra pool through the writer, returns the price exactly to its start (`tickBefore ==
tickAfter`) — CALLED-green. The path is deliberately ordered: first make the tree **buildable and
reproducible** (toolchain + tracked foundation), then the reusable **multicall**, then the writer's
**plugin/fee** preconditions, then the **execution + closure** proof that consumes all of them.

## Phase Details

### Phase 20: Toolchain pin & foundation tracking
**Goal**: The model builds reproducibly for anyone, not just this working tree.
**Depends on**: Nothing.
**Requirements**: TOOL-01, INTG-02
**Success Criteria**:
1. A `.plank-version` pins the local `plank_dev` build and the Makefile `PLANK` resolves to it; the stale PATH `v0.1.1` is never used (TOOL-01).
2. `plank build` of the writer succeeds against the pinned compiler with no dependency errors (TOOL-01).
3. `lib/Algebra`, `foundry-scripts/mev_tax_model_one/DeployAlgebraFactory.s.sol`, and the spec are tracked in git (submodule or vendored), so a fresh clone has them (INTG-02).

### Phase 21: Resolve the solc `--via-ir` SIGSEGV
**Goal**: `forge test` compiles and runs the Solidity/Algebra suite again.
**Depends on**: Nothing (parallelizable with 20).
**Requirements**: TOOL-02
**Success Criteria**:
1. The `--via-ir` solc crash is diagnosed to a named cause (a specific contract / OOM / a solc-version bug) — not guessed.
2. `forge build --via-ir --optimize` exits 0 on the model tree.
3. `forge test --match-path 'test/models/mev_tax_model_one/*' --via-ir --optimize` runs (pass or fail, but no crash).

### Phase 22: Generic multicall plank library
**Goal**: A reusable batch executor the test drives and the pool calls back into.
**Depends on**: Phase 20 (reproducible plank build).
**Requirements**: EXEC-02 (#27 — design discussed there)
**Success Criteria**:
1. `multicall(address pool, bytes[] calls)` executes each pre-encoded call via `@evm_call(pool, calls[i])`, in order.
2. Any failing call reverts the whole batch (or the ruled failure semantics from #27).
3. Reentrancy-safe under the swap callback firing back into the writer mid-batch.
4. plank-compile-verified against the pinned compiler; CALLED-green deferred to Phase 24.

### Phase 23: Plugin config + `beforeSwap` + fee-0
**Goal**: The pool will actually execute the writer-routed swaps.
**Depends on**: Phase 20.
**Requirements**: EXEC-03, EXEC-04
**Success Criteria**:
1. The writer's `pluginConfig` sets the `beforeSwap` flag and implements a `beforeSwap` hook that returns validly, so a flagged swap does not revert on an unimplemented hook (EXEC-03).
2. The pool fee is set to 0 and asserted before the replay, so the full `dQx` moves the price (§6.3) (EXEC-04).
3. plank-compile-verified; runtime behaviour proven in Phase 24.

### Phase 24: VolumePath execution & closure
**Goal**: The differential test proves price invariance under the full path, CALLED-green.
**Depends on**: Phases 21, 22, 23.
**Requirements**: EXEC-01, INTG-01
**Success Criteria**:
1. The writer's `algebraSwapCallback` pays each swap leg correctly under a real swap (EXEC-01 validated).
2. The test pre-encodes the `dQx` batch (sign-map, band-edge limits, last-swap price-limit at `SQRT_PRICE_1_1`, hookData = tokens[‖shock]) and drives it via the writer's multicall; the temporary test-side callback + `address(this)` mint are deleted (INTG-01).
3. `tickBefore == tickAfter` holds exactly, and each swap fully consumed its `dQx` (under-fill = loud failure) (INTG-01).
4. Runs CALLED-green through FFI-deployed bytecode (not merely plank-compiled). Real closure needs #25's fixture; until it lands, the test self-skips honestly.

## Execution Order

Strictly: (20 ∥ 21) → 22 → 23 → 24. Toolchain/foundation first (nothing verifies without a build);
multicall before the writer preconditions that assume it; execution+closure last, since it consumes
the multicall, the plugin/fee preconditions, and a runnable `forge test`.
