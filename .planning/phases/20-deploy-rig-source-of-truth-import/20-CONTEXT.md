<domain>
## Phase Boundary

Import the plank workstream's binding artifacts onto this branch (never re-typed), stand

<decisions>
## Implementation Decisions

### Import mechanism — VIA DEVELOP (upstream gate)
- **The plank workstream merges `feat/plank` → `develop` FIRST; this branch then
  cherry-picks / path-checkouts the artifacts FROM `origin/develop`** (user decision,
  overriding the roadmap's assumption of importing directly from `origin/feat/plank`).
- Consequence: **Phase 20 execution has an upstream gate** — it cannot start until the
  plank→develop merge lands. The executor must verify the artifacts exist on
  `origin/develop` before importing; if absent, the phase is BLOCKED on cross-track
  coordination (ping issue #13 / the plank peer), not on anything local.
- The acceptance content-diff target therefore becomes the recorded `origin/develop`
  ref (the pin file's ref), not `feat/plank @ df7088f`. The roadmap's SC-1 wording
  ("identical to origin/feat/plank @ df7088f") is superseded on this one point by this
  decision; content-identity to the RECORDED ref is what's checked.
- Import unit: the exact binding paths only (five `foundry-scripts/deploy/` files, V2
  `src/interfaces/<namespace>/*.plk` set, `.planning/rpc-api-volorder-v2-HANDOFF.md`,
  `notes/DATA_CONTRACT.md`, `notes/UNITS_AND_SCALES.md`) — not a full develop merge in
  this phase (PR #9 reviewability). If a transitively-required file surfaces (e.g. a
  lib a deploy script imports that isn't on this branch), import it the same way and
  record it in the pin file — never re-type it.

### Provenance
- A committed **pin file** at
  `.planning/phases/20-deploy-rig-source-of-truth-import/IMPORT-PIN.md` listing: the
  source ref (branch + commit sha on `origin/develop`), and per-file sha256 of every
  imported artifact. The import commit's message also names the ref.
- The acceptance check re-diffs the imported files against the recorded ref —
  machine-checkable, survives branch movement.

### Rig manifest
- **Format: JSON, parsed by the Haskell drivers at startup with `aeson`** (already a
  dependency). Language-neutral so the v6.0 subgraph tooling and shell can read it too.
  Parse failure = loud startup failure, never a silent default.
- **Split storage:** static pins (selectors, topic0s, canonical signature strings) live
  in a COMMITTED file; per-deploy contract addresses go to a GITIGNORED
  `rig-manifest.json` regenerated by every deploy. The committed static file is what
  the signature-recomputation pin tests check against the interface `.plk` files.
- **Address source: foundry's `broadcast/*/run-latest.json` files (authoritative,
  machine-readable), cross-checked against the deploy scripts' printed console lines —
  any mismatch is a loud failure.** Console-log parsing is the cross-check, never the
  primary path; chain-scanning re-derivation is forbidden.

### Literal purge (SC-3)
- **Full purge: every address, selector and topic0 under `offchain/` moves to the
  manifest** — including `Sample.hs`'s existing literals (`account`, `order_manager`,
  `price_setter_hook`). `Main.hs` reads the manifest at startup.
- The RPC URL (`http://127.0.0.1:8545`) is NOT in scope for the purge (neither an
  address-on-chain, selector, nor topic0) — it stays a plain default.
- The grep-style check for stray literals therefore needs no whitelist: any
  `0x`-prefixed 20-byte address, 4-byte selector, or 32-byte topic0 outside the
  manifest/static-pin files is a failure.

### Rig lifecycle
- **One command: `offchain/rig/deploy-rig.sh`, and it OWNS anvil** — kills any stale
  anvil, starts fresh, runs the four deploy scripts in the documented order (with
  `INIT_TS`/`INIT_TICK` seeding for RealizedVolatilityMod), writes the gitignored
  manifest from the broadcast JSONs (console cross-check), prints a summary.
- Lives under `offchain/` (this workstream's territory) — the plank-owned `Makefile`
  is NOT edited.
- SC-5's reproducibility ("second run from scratch produces the same contract set")
  is the script run twice.

### Claude's Discretion
- Manifest JSON schema (field names, nesting per contract) — keep it obvious and
  stable; the Haskell record types mirror it.
- `INIT_TS`/`INIT_TICK` seed values (any nonzero seed satisfying SC-2's "NONZERO
  packed timepoint" check).
- Exact pin-test placement (cabal test-suite vs repl-driven script) — consistent with
  how Phase 21's signature-derived pin tests will be structured.
- Shell script hygiene (set -euo pipefail, anvil PID handling, port collision
  behavior).

</decisions>

  warnings` stanza).

  before any RPC call.
