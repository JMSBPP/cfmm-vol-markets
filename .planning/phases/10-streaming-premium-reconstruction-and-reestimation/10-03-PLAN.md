<objective>
Build the epoch-to-block index that every accumulator read is keyed on, and measure whether the free
public endpoint can actually sustain the bulk read.

The premium accumulator must be sampled at a specific block for each daily epoch boundary — but the
Phase-9 swap-tick cache carries **no block numbers** (it is `timestamp_unix,tick` only), so the map
must be constructed. RESEARCH forbids assuming 2-second Base blocks: a drift of even 30 blocks
straddles an epoch boundary and silently misattributes a day of fee accrual.

This plan also answers RESEARCH Open Question 3 — whether `mainnet.base.org` sustains thousands of
sequential archive calls — **before** plan 10-06 commits to an 8k-15k call run.

Purpose: a wrong block index corrupts every downstream premium in a way the reconciliation gate
would detect only as diffuse noise, not as a locatable bug.
Output: `Chain.BlockIndex`, its offline spec, the materialised `epoch-blocks.csv`, and a measured
throughput figure.
</objective>


- `findBlockAtOrAfter env targetTs (lo, hi)` bisects on block number over `ethGetBlockByNumber`,
  returning the FIRST block whose timestamp is `>= targetTs`. Establish the initial bracket from
  the estimation-window endpoints (43,781,657 .. 48,879,461), and where a nominal ~2s block time is
  used to narrow the bracket, treat it strictly as a **hint** — always converge by bisection and
  assert the postcondition (`ts(b) >= target` and `ts(b-1) < target`) before returning. If the
  postcondition fails, return `Left` rather than a best guess.
- `buildBlockIndex env csvPath epochs`:
  - `loadBlockIndex csvPath` first; skip any epoch already present (checkpointed resumption —
    the Phase-9 `Panel.Variance` pattern; a 3k-call run that only writes at the end is a run you
    do twice).
  - For each remaining epoch, `findBlockAtOrAfter env (epoch * 86400) bracket`, then
    **append the row to disk immediately** via `appendBlockIndexRow`.
  - Narrow each subsequent bisection's lower bracket to the previous epoch's block (the map is
    monotone), which cuts the probe count materially.
  - On any `Left` from the RPC, stop and return `Left` with the epoch that failed — do NOT skip
    the epoch and continue, and do NOT substitute an interpolated block number. A missing epoch
    must be visible, not silently filled.
- CSV schema, with a `#` provenance banner naming the RPC URL, the build date, and the epoch rule:
  `epoch,block_number,block_timestamp`.
- **Import `Panel.Build.dailyEpoch`** and use it for the round-trip assertion inside
  `buildBlockIndex`; every row must satisfy `dailyEpoch (fromTs (ebBlockTimestamp r)) == ebEpoch r`.
  Do NOT write a local `floor (ts / 86400)` — RESEARCH Pitfall 4 is exactly this, and 09-05 already
  paid for it once (the 40587 offset).
