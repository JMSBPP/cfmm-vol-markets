## Design decisions this plan implements

Read `03-CONTEXT.md` in full first. The three that shape every task here:

1. **The oracle is Panoptic's LIBRARY, not our arithmetic.** Expected values are built with
   `TokenId.wrap(0).addPoolId(…).addLeg(…)`. Field decoders like
   `(tid >> (64 + 48*leg + 1)) & 0x7f` reuse the implementation's own bit math and go green together
   with a wrong offset — they are supporting assertions only.
2. **Geometry is held FIXED at the floor's golden vector; the fuzz varies only the payload.** The
   4-leg geometry is already proven by `VolOrderToPanopticTokenId.t.sol`'s 10 golden vectors
   (`width=1000, ts=10, vol=1, spread=0x8000` → bucket `[-500,500]`, `i* = 0`, strikes
   `[-375,-125,125,375]`, widths `[25,25,25,25]`). Phase 3 changes only the payload-driven fields, so
   re-deriving geometry in the test would add a second thing to get wrong without covering anything
   this phase touches.
3. **Free offset.** The payload word lives in trailing calldata; the test encodes its ACTUAL byte
   position into the descriptor.

2. Constants — the golden geometry, copied verbatim from the floor's vector, and the payload layout:

```solidity
    // The golden VolOrder: width=1000, ts=10, vol=1 (=> tick 0), spread=0x8000 (~0.5)
    // => bucket [-500,500], i*=0, split +-250 => legs [-500,-250],[-250,0],[0,250],[250,500]
    uint256 internal constant VO = /* packed per VolOrder.plk V2 layout; build with _packVO */ 0;
    int24[4] internal STRIKES = [int24(-375), int24(-125), int24(125), int24(375)];
    uint256 internal constant W = 25;      // each leg's width, in tickSpacings
    uint256 internal constant TS = 10;

    // Extra(T) descriptor layout (src/types/Extra.plk)
    uint256 internal constant FLAG_PANOPTIC   = 0x01;
    uint256 internal constant EXTRA_OFF_FLAGS = 248;
    uint256 internal constant EXTRA_OFF_OFFSET = 216;
    uint256 internal constant EXTRA_OFF_LEN   = 200;
    uint256 internal constant PANOPTIC_BITS   = 40;   // 4*(7+1) + 8

    // FLAG_PANOPTIC payload layout: leg k at [8k..8k+7], ratio 7b @8k, tokenType 1b @8k+7,
    // vegoid 8b @32.  STRIDE IS 8, NOT 7.
    uint256 internal constant PAYLOAD_LEG_STRIDE = 8;
    uint256 internal constant PAYLOAD_OFF_VEGOID = 32;

    // Harness call frame: selector 0 | packedVO 4 | poolId 36 | assetBit 68 | descriptor 100
    uint256 internal constant FIRST_FREE_CALLDATA_BYTE = 132;
```

3. Helpers — descriptor and payload builders, and the raw call that appends trailing calldata:

```solidity
    function _descriptor(uint256 byteOffset) internal pure returns (uint256) {
        return (FLAG_PANOPTIC << EXTRA_OFF_FLAGS)
             | (byteOffset    << EXTRA_OFF_OFFSET)
             | (PANOPTIC_BITS << EXTRA_OFF_LEN);
    }

    function _payload(uint256[4] memory ratio, uint256[4] memory tt, uint256 vegoid)
        internal pure returns (uint256 p)
    {
        for (uint256 k = 0; k < 4; k++) {
            p |= (ratio[k] & 0x7f) << (k * PAYLOAD_LEG_STRIDE);
            p |= (tt[k]    & 0x01) << (k * PAYLOAD_LEG_STRIDE + 7);
        }
        p |= (vegoid & 0xff) << PAYLOAD_OFF_VEGOID;
    }

    /// Calls tokenIdWithPanopticExtra with `padWords` words of padding before the payload, so the
    /// descriptor's offset genuinely varies and is genuinely followed.
    function _richTokenId(
        uint256 poolId, uint256 assetBit, uint256 payload, uint256 padWords
    ) internal returns (bool ok, uint256 tid) {
        uint256 off = FIRST_FREE_CALLDATA_BYTE + padWords * 32;
        bytes memory data = abi.encodeWithSelector(
            bytes4(0xef8b8dd5), VO, poolId, assetBit, _descriptor(off)
        );
        for (uint256 i = 0; i < padWords; i++) data = abi.encodePacked(data, uint256(0));
        data = abi.encodePacked(data, payload);
        bytes memory ret;
        (ok, ret) = harness.call(data);
        if (ok) tid = abi.decode(ret, (uint256));
    }
```

4. **The expected-value builder — Panoptic's library, and nothing else:**

```solidity
    /// Build the expected tokenId with PANOPTIC'S OWN encoder. This is the oracle.
    /// addLeg(legIndex, optionRatio, asset, tokenType, isLong, riskPartner, strike, width).
    /// riskPartner == legIndex: the Plank map self-partners every leg (all-long defines no spread).
    /// The 64-bit poolId field is (tickSpacing << 48) | (poolId & 0xffffffffffff): the Plank map
    /// writes those two with separate calls, Panoptic writes them as one addPoolId.
    function _expected(
        uint256 poolId, uint256 assetBit, uint256[4] memory ratio, uint256[4] memory tt
    ) internal view returns (uint256) {
        TokenId t = TokenId.wrap(0).addPoolId(
            uint64((TS << 48) | (poolId & 0xffffffffffff))
        );
        for (uint256 k = 0; k < 4; k++) {
            t = t.addLeg(k, ratio[k], assetBit, tt[k], 1, k, STRIKES[k], int24(int256(W)));
        }
        return TokenId.unwrap(t);
    }
```
