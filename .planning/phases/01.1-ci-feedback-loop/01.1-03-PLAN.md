### Why the JS action was NOT chosen — resolved at planning time, from source

`foundry-rs/foundry-toolchain@v1` was read directly (`action.yml` + `src/index.ts`) rather than
assumed. Three findings decided it:

- `src/index.ts` sets `const FOUNDRY_DIR = path.join(os.homedir(), ".foundry")` and installs
  there. On a **persistent self-hosted** runner, `$HOME/.foundry` is the box's real, shared
  foundry directory — the same one a human's `foundryup` writes. Using the action would have this
  *unattended* workflow rewrite the machine's default `forge` on every push. That is the exact
  hazard the pin exists to eliminate, reintroduced by the tool meant to fix it.
- `runs: using: "node24"`. `develop-gate` proves this runner executes JS actions (it runs
  `actions/checkout@v4`, node20), but node20 is not node24; node24 needs a recent
  `actions/runner`. The runner's agent version is unverified, so the action carries an
  unnecessary and untested dependency.
- `cache: true` is the default and drives `@actions/cache` traffic for `~/.foundry/cache` RPC
  data, which is pointless for a suite that runs `--offline`.

**The chosen mechanism instead:** the same `foundryup` the action itself drives (same pinned
installer commit), but into a **pin-keyed, non-shared** directory `$HOME/.foundry-pins/$VERSION`,
prepended to the job's `PATH` via `$GITHUB_PATH`. Properties: nothing outside the job is mutated;
a second job cannot collide (different pins get different directories, and same-pin concurrent
installs are serialized with `flock`); the install is paid once per pin on a persistent box
rather than per run; and the pinned binary beats the system `forge` because `$GITHUB_PATH`
prepends. This is written up as section 5 of `notes/TOOLCHAIN_PINS.md` (plan 02).

**Residual unknowns this plan does not pretend to have settled** — plan 04 reads them off the
actual run: whether the runner has outbound access to `raw.githubusercontent.com` and the Foundry
release host; whether `flock` is present; and which `forge` the runner had installed before
(`which -a forge` in the stamp step is what records it). The workflow is written so each of these
fails loudly with a named cause rather than silently proceeding.

### Skip-ledger decision: reuse develop-gate's, and guard the copy

The push build runs the **same** `--skip` ledger and the **same** `--fuzz-seed 4880`.
Rationale: the push build's job is to predict the gate. A push build measuring a *different*
surface would go red on pre-existing known-broken families (`*PriceSetterHook*`, `*VolRangeWidth*`,
`*SpreadTickAssimetryHelper*`, `*PanopticVegaLens.t.sol*`) that the gate deliberately excludes —
training everyone to ignore it, which is worse than not having it. A different seed would make the
fuzz surface differ run-to-run between the two paths for reasons nobody could attribute.

The cost is a second copy of the ledger, and copies drift. Extracting it into a shared script or
Makefile target is NOT available: the phase constraint forbids altering `develop-gate`'s ledger
line. So the copy is kept and **guarded**: `scripts/check-ci-skip-ledger.sh` extracts the quoted
patterns and the seed from both files and fails on any difference. It is pure `grep`/`diff` — no
toolchain — so it runs as the first step of the job and is also runnable locally.

    #!/usr/bin/env bash
    # The push build (.github/workflows/push-build.yml) runs a COPY of develop-gate's --skip
    # ledger and fuzz seed, on purpose: a push build that measures a different surface than the
    # gate stops predicting the gate, and would go red on the pre-existing known-broken families
    # the gate deliberately excludes -- which trains everyone to ignore it.
    #
    # Two copies drift. Extracting the command into one shared place is not available: the ledger
    # line in develop-gate.yml is not allowed to move. So the copy is guarded here instead. Red
    # means the two workflows would measure different surfaces; fix the copy, do not delete the
    # check.
    #
    # Pure grep/diff. No forge, no make, no node. Runs as the FIRST step of the push job (so a
    # divergence costs seconds, not a full build) and is runnable locally.
    set -euo pipefail

    ROOT="$(git rev-parse --show-toplevel)"
    GATE="$ROOT/.github/workflows/develop-gate.yml"
    PUSH="$ROOT/.github/workflows/push-build.yml"

    for f in "$GATE" "$PUSH"; do
      [ -f "$f" ] || { echo "ERROR: missing $f" >&2; exit 1; }
    done

    # Comment lines are STRIPPED FIRST and that is load-bearing: develop-gate.yml's ledger comment
    # names the same patterns unquoted, and a future comment must not be able to satisfy this
    # check. Consequence: no comment in either workflow may contain a "*...*" quoted glob.
    skips() { grep -v '^[[:space:]]*#' "$1" | grep -oE '"\*[^"]+\*"' | sort -u; }
    seed()  { grep -v '^[[:space:]]*#' "$1" | grep -oE 'fuzz-seed[[:space:]]+[0-9]+' \
                | tr -s '[:space:]' ' ' | sort -u; }

    rc=0

    if ! diff -u <(skips "$GATE") <(skips "$PUSH") > /tmp/skip-ledger.diff 2>&1; then
      echo "ERROR: --skip ledger diverges between develop-gate.yml and push-build.yml" >&2
      echo "       (-) is develop-gate, (+) is push-build:" >&2
      sed 's/^/       /' /tmp/skip-ledger.diff >&2
      rc=1
    fi

    if ! diff -u <(seed "$GATE") <(seed "$PUSH") > /tmp/skip-seed.diff 2>&1; then
      echo "ERROR: --fuzz-seed diverges between develop-gate.yml and push-build.yml" >&2
      sed 's/^/       /' /tmp/skip-seed.diff >&2
      rc=1
    fi

    # A guard that passes when it found nothing to compare is not a guard. The gate has four
    # entries and one seed today; require BOTH sides to be non-empty so an accidental YAML
    # restructure that hides the ledger from the extractor reddens instead of silently agreeing.
    n_gate="$(skips "$GATE" | grep -c .)" || true
    n_push="$(skips "$PUSH" | grep -c .)" || true
    if [ "$n_gate" -eq 0 ] || [ "$n_push" -eq 0 ]; then
      echo "ERROR: extracted 0 --skip patterns (gate=$n_gate push=$n_push) -- the extractor no" >&2
      echo "       longer sees the ledger. Vacuously-equal is NOT parity." >&2
      rc=1
    fi
    if [ -z "$(seed "$GATE")" ] || [ -z "$(seed "$PUSH")" ]; then
      echo "ERROR: extracted no --fuzz-seed from one or both workflows" >&2
      rc=1
    fi

    if [ "$rc" -eq 0 ]; then
      echo "skip-ledger parity OK: $n_gate patterns, seed $(seed "$GATE" | tr -d ' ' | sed 's/fuzz-seed//')"
    fi
    exit "$rc"

    # -------------------------------------------------------------------------

    # `environment:` approval and is the merge authority. Adding a push trigger there would
    # either demand a second human approval per push, or -- if the approval were relaxed to
    # avoid that -- create a push path into the merge gate. So the feedback loop lives HERE:
    # a separate workflow with NO environment, NO approval, NO secrets and NO authority over
    # merges. develop-gate is untouched as the PR/merge gate.
    #
    # Requirement CI-07 (immediate unattended compile feedback) + CI-05/CI-06 (pinned,
    # stamped toolchain). Phase 1.1.

    on:
      push:
        branches-ignore:
          - develop
        # `develop` is excluded because merges land there through the PR gate: a push build on
        # develop would be a second, unapproved build of code develop-gate has already judged.
        #
        # No `tags:` key, so tag pushes do not trigger this (a `push` event with only

        # No `paths-ignore:` ON PURPOSE. CI-07 says a push to any branch other than develop
        # IMMEDIATELY triggers a build. A path filter reintroduces "pushed but never compiled"
        # for whatever it excludes -- the exact hole this workflow closes.

      # cfmm-build executor that develop-gate also needs; without this, a burst of pushes
      # queues N full builds and starves the PR gate behind them.
      group: push-build-${{ github.ref }}
      cancel-in-progress: true

      contents: read

    #
