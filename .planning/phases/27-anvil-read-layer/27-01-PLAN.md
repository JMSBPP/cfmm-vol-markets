# Plan 27-01 — One endpoint rule, producer included

## Context

CHAIN-06 says *"nine sites, one rule."* **MEASURED: ten files** name `ETH_RPC_URL` or
`127.0.0.1:8545` — four `*/Rpc.hs` providers, `app/Main.hs`, `app/CheatSwapProof.hs`,
`rig/deploy-rig.sh`, `rig/capture-batch-return.sh`, `rig/capture-cheat-swap-proof.sh`, and
`offchain/spec/types.md`. **Re-count at execution and record what you get.** The tenth is a spec
document — decide deliberately whether prose counts as a site, write the decision down, and
remember prose sits inside a grep's blast radius (25 recorded instances).

CHAIN-07 is the half that is easy to fake: a consumer-only resolver leaves the **producer** free to
bind a different endpoint, so `deploy-rig.sh` starts anvil on one port and the reads go to another.
The requirement's own words: *"A consumer-only resolver does NOT retire the requirement."*

**`deploy-rig.sh` is in `offchain/rig/` — that IS this workstream's territory.** `src/`, `test/`,
`foundry-scripts/`, `Makefile`, `foundry.toml`, `.github/` are not.

## Tasks

### Task 1 — `Chain.Endpoint`: the resolver and the manifest

Create `offchain/lib/Chain/Endpoint.hs` exporting:

- `resolve_endpoint :: IO String` — `ETH_RPC_URL` if set **and non-empty**, else
  `http://127.0.0.1:8545`. An empty variable must not resolve to the empty string; that is the
  `"" == ""` shape this repo has hit six times.
- `endpoint_sites :: [FilePath]` — the manifest, one entry per site, each with a written note of
  what kind of consumer it is.
- `default_endpoint :: String` — stated **once**, so a site can be checked for hardcoding it.

Register the module in `aeson_storage_path` **in this same task** (`Main.hs:8994`'s scan is
bidirectional) and re-measure both floors from what `find` PRINTS. They are at **67 / 77** after
26-04 — confirm against the tree.

### Task 2 — The census, in both directions (CHAIN-06)

Add to `offchain/test/Main.hs`, registered in `core_checks`:

1. `every_endpoint_site_resolves_rather_than_hardcodes` — for each entry in `endpoint_sites`, assert
   the file **exists** (a `grep -c` over a missing file prints 0 and would pass — this bit 25-03),
   then assert it names the resolver and does **not** hardcode `127.0.0.1:8545` outside the one
   place `default_endpoint` is defined.
2. `the_endpoint_site_census_grows_with_the_tree` — bidirectional: everything on disk naming
   `ETH_RPC_URL` or the default host is in `endpoint_sites`, and everything in `endpoint_sites` is on
   disk. **This is what stops a tenth consumer being added silently.**
3. `an_empty_eth_rpc_url_does_not_resolve_to_the_empty_string` — set it to `""`, assert the default
   comes back.

**Firing inputs, each to be OBSERVED:** hardcode the default into one provider → check 1 names that
file; delete a site from `endpoint_sites` → check 2's `unlisted` arm names it; add a phantom path →
check 2's `phantom` arm names it; make `resolve_endpoint` return `getEnv` unguarded → check 3.

### Task 3 — The producer binds the same endpoint (CHAIN-07)

`offchain/rig/deploy-rig.sh` must derive anvil's `--host`/`--port` **and** the deploy `--rpc-url`
from one `ETH_RPC_URL`, and assert `cast chain-id` against the expected value **before** any
`--broadcast`.

4. `the_producer_and_the_consumers_bind_one_endpoint` — assert `deploy-rig.sh` derives host and port
   from the resolved value rather than naming a literal port, and that a `chain-id` assertion appears
   **before** the first `--broadcast` in file order.

**Firing input:** move the `chain-id` assertion below the first `--broadcast` and observe the check
name the line numbers. Ordering asserted by position is fragile (26-03 learned this when a refactor
voided a line-number gate), so **also** assert the assertion exists at all, so a deletion reddens
even if positions shift.
