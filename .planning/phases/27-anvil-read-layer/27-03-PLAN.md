# Plan 27-03 — Fixture identity, and close the phase

## Context

CHAIN-05: the published fixture records `pool` (string address), `blockNumber` (**string**) and
`chainId`, so the consuming forge test can **attach** to a pool rather than construct one.

**`blockNumber` is a string for a measured reason** — it can exceed the 53-bit double-exact ceiling,
and this repo has already been bitten by exactly this class: BYTE-04 measured `dQx[0]` as a `Double`
losing **32 wei**, which would have executed the wrong swap amounts. Do not take the reason on
faith: **observe it.** `9007199254740993` (2^53 + 1) through a JSON `Number` round-trip comes back
`9007199254740992`. Assert that, so the string choice is evidenced rather than asserted.

## Tasks

### Task 1 — Pool identity in the fixture (CHAIN-05)

Extend the fixture shape with `pool`, `blockNumber` (string), `chainId`. Register in `core_checks`:

1. `the_fixture_carries_the_pool_identity_it_was_solved_for` — all three fields present, `pool` a
   20-byte hex address that is **not** the zero address (the zero address has passed hex-shape guards
   here before), `blockNumber` a string of digits, `chainId` present.
2. `a_block_number_above_two_to_the_fifty_three_is_OBSERVED_losing_precision_as_a_number` — the
   positive control for the string choice. Drive `2^53 + 1` through a `Number` and show it come back
   wrong; then show the string form round-trip exactly.

**Firing inputs:** emit `blockNumber` as a JSON number → check 1's type arm; set `pool` to the zero
address → check 1's zero arm; make the precision check compare a value below 2^53 → check 2 goes
green against a subject that cannot fail, so assert the chosen witness is **above** the ceiling.
