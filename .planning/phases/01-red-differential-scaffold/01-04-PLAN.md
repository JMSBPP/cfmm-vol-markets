**`## The Solidity<->spec transport boundary`** — state, as a rule:
- `SpecHelper` is the ONLY place a Foundry test may reach the Haskell spec. No test spawns a
  process, reads a spec-produced file, or calls a cheatcode against the spec directly.
- `SpecHelperProbe` is the external call boundary. It exists because a Solidity library's
  `internal` functions are inlined, so a revert inside the seam would abort the calling test
  rather than being observable. Every later phase keeps it for that reason.
- The input crossing the boundary is Plank-originated: Plank is the fuzz source, the packed
  `VolOrder` word (later, the Phase 4 `VolOrder(T)` wire bytes) is TRANSPORTED, never
  reconstructed independently on the Haskell side. Two independently constructed corpora would
  drift, which defeats the test.
- The seam's signature is
  `readTokenId(uint256 packedVolOrder, uint256 poolId, uint256[4] optionRatios) -> uint256`.
  Phase 4 widens the first parameter to the wire format; nothing else about the shape changes.

**`## Outcome contract: three states, never conflated`** — a table Phase 7 implements against:

| Outcome | Meaning | May it ever look like agreement? |
|---------|---------|----------------------------------|
| spec success | the oracle returned a `tokenId` | it IS the comparison |
| spec rejection | a Haskell guard rejected the input | no — it is compared against Plank's revert-vs-return (Phase 9, GUARD-05) |
| transport failure | the oracle was unreachable or did not answer | no — and it must never be reported as a rejection either |

Add the sentence: an unreachable oracle reported as a rejection, or a rejection reported as
agreement, is how a differential test goes silently green; distinguishing the three is therefore
a correctness requirement, not ergonomics.

**`## The wiring probe and its lifecycle`** — record all three states:
- Phase 1: `SpecHelper.isWired()` returns `false`; the probe additionally makes a live call

  probe FIRST and `vm.skip` on it.
- Phase 7: the probe becomes a live transport health check; the skip still governs, because the
  spec submodule is not on the CI runner until Phase 11.
- Phase 11 (CI-04): the probe and every `vm.skip` guarded by it are REMOVED. A deliberately
  unreachable oracle must then make `develop-gate` RED, not green-with-a-skip.

State the standing rule explicitly: **the skip is computed by the test, never configured in the
