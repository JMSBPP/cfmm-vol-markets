```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.26;

/// @title SpecHelper
/// @notice THE ONE SEAM between the Foundry test process and the Haskell executable
///         specification (`spec/src/Panoptic/NId.hs :: volOrderToTokenId`). Phase 1 ships it as
///         a STUB. See notes/DIFFERENTIAL_LAYOUT.md for the boundary this file defines.
///
/// @dev PHASE 1 CONTRACT (RED-04):
///        - `readTokenId` ALWAYS reverts with `SpecOracleNotWired`. It is a stub, NOT a
///          fallback. It must never return a value: a stub that quietly returned 0 would let
///          the differential test "agree" on a fabricated zero tokenId, which is strictly worse
///          than having no test at all.
///        - `isWired()` is the WIRING PROBE. The differential test queries it FIRST and
///          `vm.skip`s on false, so this branch pushes clean through `develop-gate` WITHOUT an
///          entry in the gate's `--skip` ledger (.github/workflows/develop-gate.yml).
///
///      MUTABILITY IS DELIBERATELY UNRESTRICTED — neither function is `view` or `pure`. Phase 7
///      implements these bodies over the transport Phase 5 chooses (`vm.ffi` or `vm.rpc`), both
///      state-mutating cheatcodes. Declaring them `pure` today would force mutability churn on
///      every call site later. solc's warning 2018 ("state mutability can be restricted") is
///      EXPECTED here; do not "fix" it by adding `view` or `pure`.
///
///      EXTENSION POINTS — later phases fill these in, they do not redesign them:
///        Phase 4  - `packedVolOrder` widens to the `VolOrder(T)` wire format bytes.
///        Phase 5  - chooses the transport and fixes the responsibility split. Not this file.
///        Phase 7  - implements both bodies, and introduces the three-way outcome so that spec
///                   REJECTION and TRANSPORT FAILURE are never conflated with each other, and
///                   neither is ever reported as agreement.
///        Phase 11 - the probe, and every `vm.skip` guarded by it, are REMOVED (CI-04).
library SpecHelper {
    /// @notice Raised by the Phase 1 stub on every call, carrying the input that was asked
    ///         about so a failure NAMES the case rather than merely reporting "not wired".
    /// @param packedVolOrder the packed VolOrder word that was to be transported
    /// @param poolId the Panoptic pool id that was to be transported
    /// @param optionRatios the (r0,r1,r2,r3) tuple that was to be transported
    error SpecOracleNotWired(uint256 packedVolOrder, uint256 poolId, uint256[4] optionRatios);

    /// @notice THE WIRING PROBE. Reports whether the Haskell spec oracle can be reached.
    /// @dev Phase 1 always returns false: there is no oracle. Phase 7 replaces this body with a
    ///      live transport health check. Callers MUST treat `false` as "skip this comparison",
    ///      NEVER as "the spec rejected this input" - an unreachable oracle masquerading as a
    ///      rejection is exactly how a differential test goes silently green.
    function isWired() internal returns (bool) {
        return false;
    }

    /// @notice Would return the Haskell spec's `tokenId` for this input.
    /// @param packedVolOrder Plank's packed VolOrder word:
    ///        skew@0..15 | volStrike@16..103 | tickSpacing@104..127 | width@128..151 |
    ///        targetVega@152..247 (src/types/pos_spec/VolOrder.plk, V2 STORAGE LAYOUT).
    /// @param poolId The 64-bit Panoptic pool id occupying tokenId bits 0..63.
    /// @param optionRatios The Haskell map's 4-tuple (r0,r1,r2,r3); the spec rejects any entry
    ///        outside 1..127. Plank does not consume these yet - that gap closes in Phase 3.
    /// @return The spec's tokenId. PHASE 1: unreachable; this function always reverts.
    function readTokenId(uint256 packedVolOrder, uint256 poolId, uint256[4] memory optionRatios)
        internal
        returns (uint256)
    {
        revert SpecOracleNotWired(packedVolOrder, poolId, optionRatios);
    }
}

/// @notice Thin EXTERNAL boundary around the SpecHelper seam.
/// @dev A library's `internal` functions are INLINED into the caller, so a revert inside
///      `SpecHelper.readTokenId` would abort the calling test itself. Routing through a real
///      external call is what lets the wiring probe OBSERVE "not wired" instead of dying of it,
///      and it is what makes the stub's revert assertable with `vm.expectRevert`.
///
///      Phase 7 keeps this boundary for the same structural reason: it is how a TRANSPORT
///      FAILURE stays catchable, and therefore reportable as something other than a spec
///      rejection or an agreement.
contract SpecHelperProbe {
    function readTokenId(uint256 packedVolOrder, uint256 poolId, uint256[4] calldata optionRatios)
        external
        returns (uint256)
    {
        return SpecHelper.readTokenId(packedVolOrder, poolId, optionRatios);
    }
}
```
