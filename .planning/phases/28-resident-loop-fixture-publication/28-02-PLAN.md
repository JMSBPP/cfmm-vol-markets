`process_block` for block `b`: fetch `[b, b]` logs; for each log in `(blockNumber, logIndex)` order —
`event_identity`, then `ledger_seen` (a seen event is skipped with NO row and no solve), then
`decode_shock`, then the pinned reads at `AtBlock b`, then `Fee.Split.split_for`, then
`content_key`/`decide`, then `classify`. Accumulate `LedgerRow`s. **Publish for every outcome
carrying an artifact, including `elided`** — the fixture tracks the newest EVENT, stamped with that
event's block. Then ONE `ledger_commit_block b rows`. A `cl_halts` outcome returns before the commit
so the watermark is NOT advanced past that block. A block with no logs commits an empty row list and
advances the watermark anyway — that is what makes a restart skip a quiet stretch instead of
re-scanning it.

`adopt_identity :: KeyIdentity -> Maybe ToolchainIdentity -> (KeyIdentity, Maybe String)` — the USER
RULING, as a pure function: when the stashed `ToolchainIdentity` differs from the pinned one, return
the NEW identity and a note naming both, the block and the event; the loop logs the note and
continues. It does not halt. The rows written after the switch carry the identity that keyed them,
so the change is reconstructible from the ledger.

`block_report_line :: BlockReport -> String` — ONE JSON line per block, rendered by hand (no
`aeson`: `offchain/lib/Loop` is on the scanned artifact path, and `render_fixture_identity` is the
precedent for hand-rendering what leaves this workstream). Fields, exactly:
`{"block":N,"events":N,"published":true|false,"fixture":"…","outcomes":[{"tx":"0x…","logIndex":N,"outcome":"…","keyPrefix":"…"}]}`
with `keyPrefix` the first 16 hex characters of the content key, or `""` for an inadmissible event.
