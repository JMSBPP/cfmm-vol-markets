**(a) The shutdown, in `Loop.Run`.** One `IORef Bool` set by the interrupt handler and READ ONLY
between blocks: `run_loop` checks it after `process_block` returns and before the next range is
planned. The handler itself does nothing but set the flag — no logging, no exit, no IO on the
transaction. The haddock states the property and why it is stated as a place rather than as a
promise: a handler that exits calls `exitWith` in the middle of whatever the main thread was doing,
and "whatever it was doing" includes an open transaction.

Wrap each `process_block` call so an exception from ANY stage is caught, the block is abandoned
WITHOUT a commit, and the loop halts with the corresponding `Halt`. The commit is the last statement
in the stage list on purpose: everything before it is recomputable from the chain and the store, and
nothing before it has written anything.

**(b) `offchain/app/LoopMain.hs`**: install the handler, and on a flagged shutdown exit `0` after the
last completed block — a clean drain is not a failure. On a `Halt`, exit by `exit_code_for_halt`
after printing a final JSON line naming the event.

**(c) The battery.** Register these checks:

1. `an_exception_at_each_stage_leaves_the_watermark_unadvanced` — the requirement, and the word is
   EACH. Enumerate the stages of `process_block` as a list in the check, and for each one build an
   `Env` whose corresponding component raises (a `ChainSource` whose `source_logs` throws; one whose
   `source_reads` throws; a `Solver` whose `solver_run` throws; a publish action that throws; a
   `Ledger` whose `ledger_commit_block` throws). For every stage assert: `ledger_watermark` is
   UNCHANGED from before, `ledger_rows_for` finds no row for the event, the store gained no entry,
   and a subsequent clean run over the SAME block produces the rows it should — the block was
   re-processed, not skipped. Assert FIRST that the stage list is non-empty and that the clean run
   over that block DOES produce rows, or every "nothing happened" arm is satisfied by a pipeline that
   does nothing.
   FIRING INPUT: move `ledger_commit_block` ahead of the publish stage — the publish-stage arm must
   observe an advanced watermark.
2. `an_interrupt_is_observed_only_at_a_block_boundary` — drive `run_loop Resident` over a source with
   three event-carrying blocks, with the interrupt flag set by a `ChainSource` whose `source_logs`
   sets it while serving block 2. Assert: block 2's rows and watermark BOTH landed (the block that
   was in flight completed), block 3 was not processed, `run_loop` returned cleanly, and the
   watermark is exactly block 2. A flag read inside the block would leave block 2 half-committed and
   this check is what separates the two.
   FIRING INPUT: read the flag between events instead of between blocks — the check must observe a
   watermark at 1 with block-2 rows present, or rows missing with the watermark at 2.
3. `the_published_fixture_survives_an_interrupted_iteration` — publish for block 1, then interrupt
   during block 2 mid-way through publication (a publish action that writes through the real
   `publish_fixture` and then throws). Assert the file on disk still parses, still carries the ten
   artifact fields and the three identity fields, and that no `*.tmp` survives beside it. Assert the
   content key recorded in the ledger for the LAST COMPLETED block matches the run whose bytes are on
   disk — the criterion is that the fixture carries the key of a run that COMPLETED.
   FIRING INPUT: have the publish stage write the destination directly instead of through the
   rename — the parse arm must redden.
