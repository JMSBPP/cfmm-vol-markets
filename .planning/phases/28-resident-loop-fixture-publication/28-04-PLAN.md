Add to `offchain/lib/Loop/Publish.hs`:

```haskell
data PublishPrecondition
  = FixtureDirAbsent FilePath
  | FixtureDirNotADirectory FilePath
  deriving (Eq, Show)

publish_precondition :: FilePath -> IO (Either PublishPrecondition ())
```

It checks `doesDirectoryExist` and `doesFileExist` and returns a `Left` for each, and **creates
nothing on any path** — no `createDirectory`, no `createDirectoryIfMissing`, not even in a fallback.
The refusal's rendered text must carry, in one message: the RESOLVED path; the fact that this
directory belongs to the `mev_tax_model_one` workstream (issues **#24** and **#25**); the sentence
that this process will not create it; and how to fix it (land the directory on `develop`, or point
`FIXTURE_DIR` at one that exists). Two reasons the text is this specific, and they go in the
haddock: a loop that creates the directory turns a typo into a fixture published where nothing
reads it, and the consuming test SKIPS while the file is absent — so a wrong path produces a green
test on both sides and no evidence anywhere.

`publish_precondition` is called ONCE at startup in `offchain/app/LoopMain.hs`, before the first
poll, exiting `exit_code_for_precondition (FixtureDirMissing path)` = **40**. Calling it at startup
rather than at the first publication is deliberate: a loop that discovers this on its first event has
already advanced a watermark past blocks it could not publish for.

`publish_fixture` keeps its own guard as well — the two are different failures (a directory removed
while the loop runs is not the same event as one that was never there), and the startup check being
the only one would make the running loop's behaviour depend on nothing having changed.
