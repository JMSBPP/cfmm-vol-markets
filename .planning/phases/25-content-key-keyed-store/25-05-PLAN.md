<objective>
On-demand determinism verification whose two comparands cannot be the same value, and a command
whose failure is an exit code rather than a returned constructor.

Purpose: Nix shipped always-verify (`--repeat`, `enforce-determinism`) and REMOVED both in 2.13 as
"broken under many circumstances for a long time", so verification is a separate mode off the hot
path. And this repository has already been burned by a library that returns an error while the
process exits 0 — `postgresql-migration` does exactly that, which is the whole of `run_migrations_or_exit`.
So the mismatch's non-zero exit is observed as `echo $?` from a REAL subprocess, never as a value.

The named tautology — comparing a cached row to itself — is answered by TYPES, not by a comment:
`verify (cached_bytes r) (cached_bytes r)` must not type-check, and the GHC error must be OBSERVED,
in the shape 23-01 observed `[GHC-39999] No instance for 'Eq DerivedDoc'` and 24-03 observed the
refused `ProverOutcome -> ProverArtifact` accessor.

Output: `Store.Verify` (the pure verifier AND the re-solve/quarantine driver), the `store-admin`
executable, and seven checks.

**Scope note of record:** this plan carries FOUR tasks rather than the phase's usual three. The
fourth is not padding — a revision pass found STORE-02 and STORE-03 asserted by 25-05's mutation
table and by 25-08's capture while nothing in the phase ever called `store_quarantine_put` on a
mismatch or re-solved an existing key. Task 3 is that missing implementation, and it is here rather
than in a tenth plan because the guard it must not break (`verification_is_reachable_only_from_its_own_entrypoint`)
is shipped in this same plan.
</objective>
