<objective>
The store seam grows the eight operations the requirements need, and BOTH implementations get them:
the discriminating put, the append-only run log, quarantine, pin, entry count and scoped reset.

Purpose: MEASURED — `insert … on conflict do nothing returning k` returns **NO ROW** on conflict, so
the caller cannot tell "I wrote it" from "it already existed", and STORE-01 and STORE-02 both need
exactly that distinction. `on conflict (…) do update set raw = model_run.raw returning (xmax = 0)`
assigns the EXISTING row's value (`model_run.` is the table, `excluded.` is the proposed), so
first-writer-wins is preserved AND a row always comes back, with `xmax = 0` returning `t` then `f`.

**Decision of record, taken here: no new entry is added to `Store.Laws` in this phase.** The law set
is asserted against the committed capture's `law_verdicts` block in BOTH directions, so a law added
now would redden that Tier-C check until the next re-capture — five plans away. The new surfaces are
asserted as dedicated Tier-B checks against `Store.Memory`; their Postgres half is a capture
observation in plans 25-07 and 25-08. Record this reasoning in the summary.
