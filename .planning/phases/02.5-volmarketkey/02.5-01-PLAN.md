# Phase 2.5 — VolMarketKey(V) and the 40-bit Payload: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `VolMarketKey(V)` resolves a venue-tagged market key to its venue's pool identity — an SFPM-verified Panoptic `poolId` for V4 and V3, a registry-verified pool address for Algebra — and the `FLAG_PANOPTIC` payload widens to 40 bits carrying per-leg `tokenType` plus `vegoid`.

**Architecture:** A comptime type constructor over a venue tag, mirroring the established `Extra(T)` / `Shock(R)` phantom-parameter pattern so cross-venue misuse is a **compile** error. Every added field is a caller-supplied assertion checked against an independently derived truth — *the caller declares, the contract proves*. The Panoptic `poolId` is stateful (the SFPM increments the pattern on collision), so the key derives a **candidate** and verifies it against the SFPM.

import std::error::require;

// VolMarketKey(V): a market key TAGGED BY VENUE.
//
// `V` is a phantom type parameter used as a venue index, exactly as `Extra(T)` uses a region.
// `struct V { ... }` makes VolMarketKey(V4) and VolMarketKey(Algebra) DISTINCT types even though
// the fields are identical, so an Algebra key can never be read as a V4 one. Verified supported:
// plank's struct tag accepts any comptime value (std/slice.plk tags with
// `struct (R, T, arity.inner)`, whose third element is a u256 VALUE), and `is_region` is an
// ordinary fn in std/regions.plk, not a language rule.
//
// ASSET vs NUMERAIRE -- read this before touching asset_index.
// Panoptic's `asset` BIT names the CASH/collateral token that positionSize is denominated in
// (TokenId.sol:112-116 "0 if asset is token0, 1 if asset is token1"; PanopticMath.getLiquidityChunk
// "the asset is the basis of the position ... in TradFi, the asset is always cash"). THIS protocol
// calls that token the NUMERAIRE (AlgebraIntegralShocksWriterMod.plk:214). The two vocabularies use
// "asset" for OPPOSITE roles, so the mapping is a NOT -- see vol_market_key_panoptic_asset_bit.

const V4 = struct {};
const V3 = struct {};
const Algebra = struct {};

const is_venue = fn (comptime V: type) bool {
    V == V4 or V == V3 or V == Algebra
};

const VolMarketKey = fn (comptime V: type) type {
    if !is_venue(V) {
        @compile_error("VolMarketKey: V must be V4, V3 or Algebra");
    }
    return struct V {
        currency0: u256,    // sorted: currency0 < currency1
        currency1: u256,
        asset_index: u256,  // 0 => currency0 is the ASSET; the other currency is the numeraire
        fee: u256,          // V4/V3; unused on Algebra (dynamic fee)
        tick_spacing: u256, // V4 explicit; V3/Algebra verified against the pool
        registry: u256,     // V4: hooks | V3: univ3 factory | Algebra: algebra factory
        pool: u256          // V3/Algebra: the ASSERTED pool address. V4: 0
    };
};
```

// The Panoptic `asset` bit for this key. It is a NOT, NOT a copy.
//
// Panoptic's bit names the CASH token positionSize is denominated in; this protocol denominates
// vega in the NUMERAIRE and calls the OTHER currency the asset. With two currencies,
// numeraire_index = 1 - asset_index. Getting this backwards emits a STRUCTURALLY VALID tokenId

const vol_market_key_panoptic_asset_bit = fn (comptime V: type, k: VolMarketKey(V)) u256 {
    require(k.asset_index <= 1);
    1 -% k.asset_index
};

// std has NO general external-call helper: across std/ at 00c0a1a only std/precompile.plk makes
// calls, hardcoded to precompiles 0x01-0x05. This is that idiom -- malloc, mstore, staticcall,
// require(success), mload -- matching both std and AlgebraIntegralShocksWriterMod.
const staticcall_word = fn (target: u256, args_ptr: u256, args_len: u256) u256 {
    let ret = @malloc_uninit(32);
    let ok = @evm_staticcall(@evm_gas(), target, args_ptr, args_len, ret, 32);
    require(ok);
    @mload32(ret)
};

// Selectors via std/abi.plk's compute_selector rather than pasted constants:
//   getPool(address,address,uint24)  -- univ3 factory
//   poolByPair(address,address)      -- algebra factory
// Verify the SUPPLIED pool address against the venue registry. Never CREATE2 -- SFPM V3 itself
// resolves pools this way (FACTORY.getPool(token0, token1, fee)).
const vol_market_key_verify_pool = fn (comptime V: type, k: VolMarketKey(V)) void {
    if V == V4 { @compile_error("VolMarketKey: V4 has no pool address to verify"); }
    let p = @malloc_uninit(100);
    if V == V3 {
        @mstore4(p, SEL_GET_POOL);
        @mstore32(p +% 4, k.currency0);
        @mstore32(p +% 36, k.currency1);
        @mstore32(p +% 68, k.fee);
        require(staticcall_word(k.registry, p, 100) == k.pool);
    } else {
        @mstore4(p, SEL_POOL_BY_PAIR);
        @mstore32(p +% 4, k.currency0);
        @mstore32(p +% 36, k.currency1);
        require(staticcall_word(k.registry, p, 68) == k.pool);
    }
};

// DERIVE the candidate, then VERIFY against the SFPM.
//
// The Panoptic poolId is STATEFUL: both SFPMs loop
//   while (s_poolIdToKey[poolId].tickSpacing != 0) poolId = incrementPoolPattern(poolId)
// on collision, and enforce the stored value at mint (V4:787). So a pure derivation yields a
// CANDIDATE. Verifying here makes a collision fail with OUR error at build time instead of
// Panoptic's at mint.
//
// V4 and V3 only: there is no PanopticFactoryAlgebra, so the Algebra arm has no continuation and
// must not be given a synthetic one (KEY-04).
const vol_market_key_to_panoptic_pool_id =
    fn (comptime V: type, k: VolMarketKey(V), sfpm: u256, vegoid: u256) u256 {
    if V == Algebra {
        @compile_error("VolMarketKey: the Panoptic arm accepts only V4 or V3");
    }
    let pattern = if V == V4 {
        vol_market_key_v4_pattern(k.registry)
    } else {
        vol_market_key_verify_pool(V, k);
        vol_market_key_v3_pattern(k.pool)
    };
    let candidate = vol_market_key_compose_pool_id(pattern, vegoid, k.tick_spacing);

    // getPoolId(bytes id, uint8 vegoid) -- `id` is a DYNAMIC type, so this is NOT a two-word frame.
    // Verified against SemiFungiblePositionManagerV4.sol:1369 and V3.sol:1558; both SFPMs share the
    // signature and both abi.decode the bytes (V4 -> PoolId, V3 -> address). Layout:
    //     0   selector
    //     4   offset to `id`      = 0x40
    //     36  vegoid
    //     68  id.length           = 32
    //     100 id word             (v4 PoolId, or the univ3 pool address)
    //   = 132 bytes
    let p = @malloc_uninit(132);
    @mstore4(p, SEL_SFPM_GET_POOL_ID);
    @mstore32(p +% 4, 0x40);
    @mstore32(p +% 36, vegoid);
    @mstore32(p +% 68, 32);
    @mstore32(p +% 100, if V == V4 { k.registry } else { k.pool });
    require(candidate == staticcall_word(sfpm, p, 132));
    candidate
};
```
